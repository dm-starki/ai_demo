# Клиент-серверный чат (chat_cursor_auto)

Полнофункциональное приложение чата: **React (Vite) + Ant Design** на фронтенде и **Fastify + Socket.IO + PostgreSQL** на бэкенде. Авторизация по **JWT** (access + refresh), токены хранятся в **sessionStorage**. Обмен сообщениями в реальном времени — **WebSocket (Socket.IO)**.

## Требования

- **Node.js** и **Yarn**
- **PostgreSQL** (локально доступен суперпользователь `postgres`; для инициализации см. `scripts/db-init.sh`)

## Быстрый старт (локально)

1. Установить зависимости в корне, фронте и бэкенде:

```bash
yarn install
yarn --cwd front install
yarn --cwd back install
```

2. Инициализировать базу данных (создаёт БД, схему и тестовых пользователей):

```bash
yarn db:init
```

3. Запустить фронт и бэкенд одной командой из корня:

```bash
yarn dev
```

Фронтенд: `http://localhost:5101` (браузер откроется автоматически).  
REST API: порт **5102**. Socket.IO: порт **5103**.

## Скрипты корня

| Команда        | Назначение                                      |
|----------------|-------------------------------------------------|
| `yarn dev`     | Параллельный запуск фронта и бэка для разработки |
| `yarn build`   | Сборка бэка (`back/build`) и фронта (`front/build`) |
| `yarn db:init` | SQL-инициализация БД + сиды пользователей      |
| `yarn clean`   | Удаление `build` и `node_modules` в подпроектах и корне |
| `yarn stop`    | Принудительная остановка процессов на портах 5101–5103 |

## Переменные окружения

- **Фронтенд**: `front/.env`, пример для прода — `front/.env.production.example` (все ключи с комментариями).
- **Бэкенд**: `back/.env`, пример для прода — `back/.env.production.example`.

Пароль суперпользователя PostgreSQL для `yarn db:init` по умолчанию берётся из `POSTGRES_ADMIN_PASSWORD` или **Change127** (как в задании для локальной машины).

## Структура репозитория

- `front/` — SPA на React + Vite + Ant Design + RTK Query + Socket.IO-клиент.
- `back/` — Fastify (REST) + Socket.IO (отдельный порт) + `pg`.
- `back/sql/init_db.sql` — создание роли, БД и таблиц с комментариями на русском.
- `back/sql/upd_db.sql` — последовательные миграции между версиями.

История изменений по версиям ведётся в **HISTORY.md**.
